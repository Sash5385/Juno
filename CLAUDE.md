# CLAUDE.md — правила для Juno

Juno — SaaS для онлайн-запису в салони краси, барбершопи й до майстрів (адмінка власника/майстра). Клієнтський застосунок — репозиторій Juno-client.
Стек: React 19 + Vite, Firebase (Realtime Database + rules, Cloud Functions v2 Node 22, Hosting, FCM), оплата клієнтів — Monobank (токен кожного салону).
Схема, ролі, функції: `docs/SALON-SCHEMA.md`. Тести: `tests/README.md`.

## Порядок роботи
1. Проаналізувати код і знайти зв'язані файли; для великих змін (схема, rules, оплата, календар) — спершу план: що зміниться, які файли, ризики, як відкотити.
2. Мінімальні зміни; не ламати існуючі записи, календар, бронювання (створення, перенесення, скасування, сповіщення, часові пояси).
3. Не змінювати візуальний стиль без прямого запиту. Екрани працюють від 320px (Android, iPhone, планшет).
4. Перед пушем: `npm run build`, `npm run lint`, релевантні тести з `tests/README.md` (rules-тести обов'язкові після будь-якої зміни `database.rules.json`).
5. Підсумок: список змінених файлів, ризики, ідеї — окремим списком.

## Rules і дані
- Без підтвердження не видаляти вузли даних і не змінювати чужі дані.
- Зміна `database.rules.json` — разом із тестом у `tests/rules/` (ролі: власник, майстер, клієнт).
- Токен Monobank салону живе лише в `salon_secrets` (читає тільки сервер).

## Версіонування
Файл `src/version.js` (`export const APP_VERSION = "vДД.ММ.N"`; N — порядковий номер за день), показується в Налаштуваннях.
Версія Juno й Juno-client ведеться окремо від DrivePad. Повідомлення коміту починається з версії: `v03.10.1 — опис`.

## Git і деплой
- `main` — незмінна копія DrivePad (довідка); розробка йде у робочій гілці.
- Деплой тільки вручну: Actions → «Deploy to Firebase» (потрібні secret `FIREBASE_TOKEN`, variable `FIREBASE_PROJECT_ID`). Автодеплою немає.
- Без підтвердження не виконувати: `rm -rf`, `git reset --hard`, `git push --force`, `claude --dangerously-skip-permissions`.

## Стиль спілкування
Коротко: що зроблено (1–2 рядки), файл і рядок за потреби.
